FailFirst

Give it a public GitHub repo, the buggy commit and a bug report. It explores the code in a sandbox, writes the smallest failing pytest test that captures the bug, runs it, and reports REPRODUCED, NOT_REPRODUCED or NEEDS_INFO. It never fixes the bug, never pushes and never comments.

How it works

The model only gets six tools. It never gets a shell, the network or write access to the repository.

  1. InputA repo URL, the buggy commit and the bug report text.
  2. SetupA throwaway Docker container clones the repo and installs it. It has network access only for this step.
  3. ExploreA second container with no network. The model reads the report and uses list_files, read_file and search_code.
  4. TestIt writes the smallest test that expects the correct behaviour (write_test) and runs it (run_tests).
  5. CheckA REPRODUCED claim counts only if the test fails twice with a real test failure, not an import, syntax or fixture error.
  6. Reportreport.md, run.json and the test file, plus budgets for steps, tokens, cost and time.

    Run it yourself
    
  
    The offline demo needs only Python. The full setup guide (Ollama, Docker, real repos) is in the README.
    

    git clone https://github.com/Omkar210404/Fail-First
cd Fail-First
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -e .
failfirst demo                    # scripted model, no key, no network
failfirst ui                      # web app at http://127.0.0.1:8765
